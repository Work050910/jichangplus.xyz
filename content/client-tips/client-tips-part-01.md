# Clash 核心模式解析：规则分流、全局连接与直连的区别与应用

## 导读：为什么模式选择是网络分流的第一道基石

在使用 Clash 或其现代衍生客户端（如 Clash Verge Rev、Stash、Mihomo Party）时，界面顶部的“模式（Mode）”切换选项是最核心的控制开关。然而，许多初学者由于不理解底层路由机制，要么常年开着全局模式导致国内网页加载缓慢甚至银行 App 触发异地风控；要么因分流配置不当导致关键海外站点无法访问。

弄清楚 Rule（规则）、Global（全局）与 Direct（直连）的区别，是建立条理分明、高可用网络环境的第一步。本文将从网络请求的生命周期切入，为你透彻拆解三种模式的适用边界与最佳实践。

## 三大核心模式底层工作原理解析

### 1. 规则模式（Rule Mode）—— 智能按需调度的首选
在规则模式下，Clash 充当一个高度智能的交通警察。当应用程序发起一个网络请求时，Clash 会从上到下逐条扫描配置文件中预设的分流规则列表：
- 如果请求的域名或 IP 命中代理规则（如 Google、GitHub），数据包被打包发往指定的海外代理节点；
- 如果请求属于国内大厂服务（如微信、淘宝、腾讯视频）或命中 GEOIP(CN) 规则，数据包直接由本地网络发起直连；
- 如果未命中任何特定规则，则进入最后的 MATCH 兜底策略。
**适用场景**：日常全天候常驻运行。既能享受流畅的海外服务，又能保证国内应用全速直连且不泄露本地 IP。

### 2. 全局模式（Global Mode）—— 强制接管与故障排查
在全局模式下，Clash 忽略所有的域名与 IP 分流规则列表。除局域网私有地址外，设备发出的所有网络请求均无条件流向用户当前手动选定的那一个代理节点。
**适用场景**：
- **故障排查**：当某个海外冷门网页在规则模式下打不开时，切到全局模式可快速验证是服务商节点问题还是本地分流规则漏配；
- **特定业务强制单出口**：在需要全程保持单国家 IP 纯净度的场景（如进行跨国支付结算或特定平台账号注册）下临时使用。

### 3. 直连模式（Direct Mode）—— 完全绕过代理引擎
在直连模式下，Clash 停止对所有外发数据包的代理中继，相当于临时停用了代理服务，所有流量均直接通过本地运营商宽带发出。
**适用场景**：进行纯国内大文件高速下载、玩国服低延迟竞技游戏、或排查本地网络与路由器物理连接故障。

## 规则模式下的规则匹配次序细节

在规则模式中，规则是按“自上而下、先命中先执行”的严格顺序生效的。典型的标准规则链结构如下：
1. **私有网络直连规则**：`DOMAIN-SUFFIX,local,DIRECT` 与 `IP-CIDR,192.168.0.0/16,DIRECT`，确保局域网打印机与路由器后台绝不走代理；
2. **专属服务分流规则**：将 OpenAI、Netflix 等特定域名导向专属的低延迟或流媒体策略组；
3. **国内白名单规则**：`GEOSITE,cn,DIRECT` 与 `GEOIP,CN,DIRECT`，确保国内数万个域名高速直达；
4. **最终兜底匹配**：`MATCH,节点选择`，处理所有未被明确定义的未知海外长尾流量。

## 常见操作误区与优化建议

- **误区一：为了省事常年开全局模式**。这不仅会白白消耗宝贵的套餐流量，还会导致国内视频网站因为检测到海外 IP 而提示“版权受限无法播放”，甚至触发微信支付异地登录保护；
- **误区二：出现连接超时立刻换节点**。在规则模式下出现超时，首先查看客户端的“连接（Connections）”面板，核实该请求究竟命中了 DIRECT 还是 PROXY。很多时候是因为分流规则将新域名误判为直连而导致连接阻断。

## 常见问题解答 (FAQ)

### 为什么在规则模式下，访问某些国内网站依然显示我在国外？
这通常是因为本地 DNS 污染或分流规则库未及时更新所致。部分国内小型网站采用了海外云厂商（如 AWS、Cloudflare）的 CDN 加速，若规则库仅按 IP 网段判定，可能将其误判为海外流量。在分流规则前追加针对该域名的 DIRECT 规则即可纠正。

### 切换模式后，正在运行的软件为什么没有立刻生效？
因为现代浏览器与许多应用程序支持 TCP Keep-Alive 和 HTTP/2 连接复用。在切换模式前已经建立的旧连接会继续保持原有通道，直到空闲超时断开。切换模式后，关闭并重新打开该软件，或在 Clash 连接面板中点击“关闭所有连接”，即可立即强制新连接走新模式。
