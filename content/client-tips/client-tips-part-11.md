# Clash Meta (Mihomo) 内核高级特性：多协议支持与路由链

## 导读：从经典 Clash 到 Mihomo 的时代跨越

在原版 Clash 核心停止维护之后，开源社区并未停下脚步，其中由全球极客共同推进的 **Mihomo（原名 Clash.Meta）** 迅速接过了演进的大旗，成为了现代 Clash 生态无可争议的事实标准与核心动力引擎。

许多读者虽然每天都在使用基于 Mihomo 的现代客户端，但对其内部蕴藏的强大高级特性知之甚少，仅仅将其当作一个普通兼容层来用。事实上，Mihomo 引入了对现代极速协议的原生支持、革命性的链式代理（Relay）路由调度，以及深度域名嗅探（Sniffer）等杀手级功能。本文将为你全面揭开 Mihomo 内核的高阶玩法。

## Mihomo 核心特性一：现代全协议谱系原生兼容

相较于原版内核对新协议的停滞，Mihomo 实现了对当下所有主流及前沿网络协议的零门槛原生支持：
- **VLESS 与 XTLS / Reality 协议**：支持最新的偷渡伪装机制，彻底摆脱传统自签证书的特征暴露，具备极强的抗封锁能力；
- **Hysteria 2（歇斯底里 2）**：基于 UDP 定制的极速拥塞控制协议，在恶劣网络丢包环境下能够暴力榨干出口带宽，是晚高峰抗降速的绝佳利器；
- **TUIC v5**：基于原生 QUIC 协议设计，具备连接极速建立（0-RTT）与多路复用无队头阻塞的天然优势。

当服务商的节点列表中提供了上述新协议节点时，只有在搭载 Mihomo 内核的客户端中，才能被正确解析并高速运转。

## Mihomo 核心特性二：链式代理（Relay / Chain Proxy）

链式代理是进阶极客最为青睐的高级拓扑玩法。它允许你的网络请求像“跳板机”一样，在多个代理节点之间依次穿梭传递：

```
[本地客户端] ──> [前置国内 BGP 专线节点 (A)] ──> [海外原生住宅落地节点 (B)] ──> [最终目标网站]
```

### 链式代理的两大核心应用场景：
1. **速度与原生 IP 兼得**：前置节点 A 选用超低延迟的高速内网专线，保障从本地到海外的极速传输；后置节点 B 选用冷门的小众原生家庭宽带 IP。两者串联后，既享受了专线的稳定高速，又获得了后置原生 IP 解锁严格风控平台的能力；
2. **极高等级的隐私保护**：目标网站只能看到后置节点 B 的访问记录，而后置节点 B 只能看到来自前置节点 A 的连接，没有任何单一方能够还原完整的通信链路。

### Mihomo 中配置 Relay 的基础语法：
```yaml
proxy-groups:
  - name: "🔗 链式跳板组"
    type: relay
    proxies:
      - "香港 IEPL 高速入口"
      - "美国 原生住宅落地"
```

## Mihomo 核心特性三：域名嗅探（Sniffer）消灭假域名与 IP 混淆

在传统的代理传输中，如果客户端发起的请求是纯 IP 形式，或者使用了加密的 TLS 握手，代理内核很难辨明其实际访问的真实域名，进而导致分流规则失效。

Mihomo 内置了强大的 **Sniffer 嗅探模块**。在 TCP 握手阶段，内核能以极低的 CPU 开销深入分析 Client Hello 数据包中的 SNI（服务器名称指示），精准提取出真实访问的目标域名，随后重新送入规则引擎执行分流裁决。这不仅能有效解决移动端 App 的“乱跑流量”问题，还能显著提高海外流媒体分流的命中准确率。

## 常见问题解答 (FAQ)

### 为什么在客户端中测试 Hysteria 2 节点，总是提示握手超时？
Hysteria 2 完全基于 UDP 协议传输。如果测试超时，首先排查本地所在网络（如公司校园网或部分地区的公共 Wi-Fi）是否存在严厉的“UDP 阻断 / QoS 压制”；其次，检查本地杀毒软件防火墙是否拦截了客户端的对外 UDP 发包。若本地 UDP 环境极度恶劣，建议退回使用 TCP 架构的传统专线节点。

### 开启链式代理（Relay）后，节点的流量是怎么扣除的？
链式代理中流经的每一个节点都会正常计算流量消耗！如果前置节点 A 扣除 1.0 倍流量，后置节点 B 也扣除 1.0 倍流量，那么该次通信在服务商后台将被分别扣除两次额度。在部署链式跳板时，需留意两个节点的倍率叠加情况。
