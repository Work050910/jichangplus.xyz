# 客户端热升级与回滚：遇到 Bug 时的版本快速还原方案

## 导读：新版本虽好，盲目更新易“翻车”

在追求网络性能与新特性的过程中，许多读者热衷于在第一时间追随软件作者的步伐，看到客户端弹出“发现新版本”的更新提示便毫不犹豫地点击升级。然而，软件开发始终伴随着不确定性，在开源社区的快速迭代中，“升级之后突然打不开了”、“新内核不认老配置导致报错”、“更新后网络频繁断流”等翻车惨剧屡见不鲜。

对于将网络工具作为日常工作基础设施的读者而言，**“稳定运行永远高于尝鲜测试”**。在享受新版本红利的同时，建立完善的配置备份与秒级版本回滚机制，是每一位网络进阶玩家的必备生存技能。本文将教你如何构筑坚不可摧的软件容灾防线。

## 客户端版本管理的核心避坑准则

在日常维护中，遵循以下三条准则能够帮你提前过滤掉 90% 的升级故障：

### 1. 绝不在工作时间或关键任务前夕随手点击升级
如果接下来半小时内你有一场重要的跨国音视频会议，或者正在紧急提交远程代码，此时弹出升级提示请坚决点击“稍后提醒”。升级应安排在闲暇时间，预留充足的测试与验证窗口。

### 2. 坚守“稳定版（Release）”，谨慎触碰“测试预览版（Pre-release / Alpha）”
很多软件在 GitHub Releases 页面会同时发布两种标签的版本。带有 `Alpha`、`Beta` 或 `Pre-release` 标识的版本主要供开发者测试新特性，往往包含未修复的边缘 Bug；对于日常主力环境，只安装经过广泛用户检验的正规 `Release` 正式版。

### 3. 更新前必须将配置目录执行完整镜像备份
这是所有安全策略的基石。在点击覆盖安装前，花 5 秒钟将本地配置文件夹完整复制一份作为保底。

## Windows 与 macOS 核心配置备份路径与方法

当软件发生严重错误无法启动时，只要配置备份还在，便能瞬间在全新环境中恢复运行：

### 1. Windows 核心文件备份路径
在 Windows 运行窗口（`Win + R`）中输入以下路径回车直达：
- `%APPDATA%\clash-verge`（或对应软件英文名）
- 将其中的 `profiles` 文件夹（存放所有订阅与自定义规则）和 `config.yaml` 复制到桌面备用。

### 2. macOS 核心文件备份路径
在 Finder 中按下快捷键 `Cmd + Shift + G`，前往文件夹：
- `~/.config/clash` 或 `~/Library/Application Support/clash-verge`
- 同样将该目录打包压缩备份至本地或私有网盘中。

## 遭遇故障时的快速版本回滚三步法

一旦升级后遭遇严重报错且无法通过简单设置修复，请按以下步骤果断实施回滚：

1. **第一步：彻底终结旧进程**  
   在任务管理器（Windows）或活动监视器（macOS）中强制结束客户端所有相关进程，防止文件被句柄占用；
2. **第二步：覆盖安装上一代已知稳定版安装包**  
   在平时建议在本地建立一个名为 `Software_Backup` 的文件夹，永久保留上一版本好用的安装安装包（如 `.exe` 或 `.dmg` 文件）。运行旧版安装程序直接覆盖安装；
3. **第三步：还原配置并验证连通性**  
   将之前备份的配置文件原封不动贴回配置目录，启动旧版客户端。网络即可在 1 分钟内完整自愈还原。

## 常见问题解答 (FAQ)

### 为什么有时候直接覆盖安装旧版本，依然提示“数据库或配置文件损坏”？
这是因为某些重大版本迭代中，新版本对本地存储的数据库（如订阅缓存数据库）进行了单向升级，旧版软件无法读取新版格式的数据库。解决办法：将配置目录彻底删除干净，仅把纯文本格式的 `yaml` 规则文件复制回来，让旧版软件重新生成干净的基础数据库即可。

### 官方 GitHub 历史版本从哪里可以下载到？
访问该开源项目的官方 GitHub 仓库页面，点击右侧的 **Releases** 标签页，向下滑动即可浏览该项目发布过的所有历史版本归档，根据发布日期挑选前一个稳定正式版下载即可。
